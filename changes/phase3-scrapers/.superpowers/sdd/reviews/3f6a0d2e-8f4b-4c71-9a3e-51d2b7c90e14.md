## 二、代码检查要点

1. **网络层**：`HttpClient` 显式 `build_opener(ProxyHandler({}))` 绕过系统代理（本机 Windows 会读注册表代理），`min_interval` 限速在请求前生效，5xx/429 退避重试、4xx 不重试，`HTTPError` 统一包成 `HttpError` 并带样例文本。`tests/test_scrapers.py` 断言了重试次数与 sleep 序列。
2. **站点隔离**：`SOURCE_NAMES` 白名单 + `get_source()` 的 `KeyError`，API 层转 400；基址全部走 Settings，冒烟用本地桩替换而不改代码。真实站点抽查（2026-11-12）米哈游 668、腾讯 2164，两站点 `normalize` 输出字段齐全。
3. **数据一致性**：`record_hash` 只覆盖 11 个可见字段，`PERSIST_FIELDS = HASH_FIELDS + ("source_url",)` 保证链接不入哈希但落库；`unchanged` 分支刷新 `scraped_at`/`is_active`/`source_url`。每 50 条 commit，单条详情失败退回列表级数据并计入 `failed`（岗位不丢）。
4. **安全与权限**：两个接口都 `Depends(require_admin)`，`scrape` 不接受任意 URL（基址来自配置），不写入任何用户私有表；任务 `params` 只存站点名与条数。
5. **可观测性**：任务 `result` 带 `created/updated/unchanged/deactivated/failed/processed/total/errors`（错误最多 5 条），前端轮询直接展示五计数。
6. **前端**：`Admin.vue` 每行站点同步按钮 + 限条数/只抓列表开关，1.5s 轮询、卸载不清定时器会残留（见遗留 3），`npm run build` 通过。

## 四、非阻塞遗留（记录在案，不阻塞本次收尾）

1. 采集与匹配未联动：采集完不会自动排队打分（与 Phase 1「只做手动触发」的既定决策一致），用户需在「岗位」页手动批量打分。
2. 没做跨轮增量游标：每次全量翻页，米哈游 14 页 / 腾讯 44 页、按 1s 限速约 1 分钟量级；未来数据量上来可加 `updatedAt` 游标。
3. `Admin.vue` 的轮询定时器在组件卸载时未 `clearInterval`（管理页常驻、影响很小），后续可加 `onUnmounted` 清理。
4. 腾讯 `experience_required` 只把中文数字归一，未覆盖「应届/不限」等口语表述（`scoring.parse_min_years` 解析不到时按 0 处理，风险与 Phase 1 相同）。
5. 采集依赖站点接口契约：米哈游 `channelDetailIds:[1]` 与腾讯 `area=cn` 是硬编码，站点改版需改适配器（已在 `design.md` 风险中登记）。
