## 2. 代码层核对

- **事务与并发**：`generate` 内 `db.add` + `db.commit`，`IntegrityError` 回滚后 `cached()` 回读再写，唯一冲突不会把任务打成 failed。
- **后台任务契约**：`run_suggestion_generate(task_id, SessionLocal_)` 经 `run_with_status` 包 running→done/failed，结果写回 `task.params["result"]`（`{suggestion_id, match_id, count, missing_keywords, honesty_warnings}` 计数），`GET /api/tasks/{id}` 已回传 `result`。
- **重试入口**：`app/api/tasks.py` 的 retry 映射包含 `suggestion_generate`，失败任务可重试。
- **鉴权隔离**：三个端点均走 `get_current_user`；`load_match`/列表/详情都以 `user_id` 约束，越权返回 404 而非 403（不泄露存在性）。
- **迁移可回退**：`c3f7a1d29b84` 用 `batch_alter_table`（sqlite 必需），`downgrade` 逆序删唯一约束/外键/索引/列；实测 `upgrade head` → 12 表且 `suggestions` 9 列，`downgrade -1` → 7 列。
- **异常面**：模型输出结构错误时 `chat_structured` 重试 3 次后抛 `LlmGatewayError`，任务落 failed 且不产生半条 `Suggestion`（有测试覆盖）。
- **前端**：`Jobs.vue` 复用既有 1.5s 轮询，`suggestTask` 与 `parseTask`/`scoreTask` 分支互不干扰；详情卡片重置时清空旧建议，避免串号；`honesty_warnings` 独立醒目块展示。

## 4. 发现（非阻塞）

1. **冒烟暴露的 litellm 冷启动问题已修但值得记档**：首次 `import litellm` 4~7 秒且默认联网拉价目表，若发生在请求线程会把事件循环卡住（实测健康检查连续超时）。现由 `app/main.py` 的 `lifespan` 同步预热 + `LITELLM_LOCAL_MODEL_COST_MAP=True`，属 Phase 2 顺带修复的稳定性缺陷。
2. **建议条数硬上限 8 条**：若真实模型返回更细碎的建议会被截断，暂无"被截断"提示；后续可在 payload 里加 `truncated: true`。
3. **`_LOCATION_HINT` 仅做展示映射**：模型若给出 `work[9].highlights` 这类越界路径，只在 UI 上显示中文名而不校验存在性，可接受（定位校验已覆盖 `original`）。
4. **前端未做"建议陈旧"提示**：匹配结果被 force 重算后，旧建议因 `resume_version` 相同仍可命中缓存（设计如此：建议绑定 match 结论 + 简历版本，不绑定分数），若用户改了权重只想看新分数，建议不会被重算——与设计 D1 一致，非缺陷。
