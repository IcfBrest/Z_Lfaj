# Proposal: 投递记录与面试跟踪（Phase 5）

## Why

Phase 0–4 解决了「岗位从哪来」「值不值得投」「简历怎么改」，但投出去之后的状态只存在于用户脑子里：投了哪些公司、面到第几轮、哪家一周没回音，全靠翻邮箱和聊天记录。缺了这一段，平台只能帮用户「准备」，帮不到「执行」。

## What Changes

1. **投递记录**：对共享岗位库或私有手动岗位「一键投递」，自动快照公司名、岗位名、当时的简历版本与匹配分，落一行投递记录。
2. **状态推进**：固定简化阶段 `已投递 → 笔试 → 面试 → Offer`，另有终止态 `已拒 / 已放弃`；每次推进记录一条时间线事件（含备注），终止态不可再改。
3. **进展总览**：投递列表按最近活动排序，标注「N 天无动静」（非终止态且 ≥ 7 天未更新），可按状态筛选，并提供各状态计数。
4. **入口打通**：共享岗位库与匹配结果页都能直接「标记为已投递」，避免二次录入。

## Scope

**In**

- `applications`、`application_events` 两张表与迁移
- 创建 / 列表 / 详情+时间线 / 状态推进 / 统计 五组接口
- 前端「投递」页（列表 + 状态筛选 + 推进 + 备注 + 时间线）与岗位页入口
- 单元测试、端到端冒烟扩展、文档更新

**Out**

- 主动通知（邮件/桌面）：本轮只做「N 天无动静」的展示与排序，不做推送
- 自定义阶段、阶段内多轮面试（一面/二面分开记）
- 附件（投递用的简历文件留档）与日历视图
- 与外部招聘平台账号联动（自动同步投递状态）

## Impact

- 新增两张表，迁移 `upgrade/downgrade` 需可逆
- 岗位库与匹配页新增按钮，属增量 UI，不改既有交互
- 不引入新的第三方依赖，不新增后台任务类型（投递记录是同步写）

## Proof

- `pytest` 覆盖状态机、快照、隔离、重复投递冲突、时间线与统计
- `tools/smoke_run.ps1` 增加一段：投递 → 推进到面试 → 列表出现「N 天无动静」字段 → 他人不可见
- `npm run build` 通过，投递页在浏览器里可筛选与推进
